# Security argument, limitations and review notes (Part A)

Material for report §5.3 ("Security: techniques & rationale" / critical
evaluation). It states what is argued by the paper, what our code and tests
actually support, and where the argument is incomplete. Tests are engineering
evidence; none of this is a machine-checked or fully rigorous proof.

## 1. What is claimed (paper §5.3)

* **Thm 5.3 (unforgeability)**: from q-SDH (Boneh-Boyen unforgeable), DL
  (Pedersen binding) and perfect soundness of Groth-Sahai (GS).
* **Thm 5.4 (strong posterior message hiding)**: from SXDH (GS is
  zero-knowledge) and perfect hiding of the Pedersen commitment.

## 2. Message hiding (Thm 5.4) -- hybrid argument and what we tested

Public output is `sigma_CS = (pi_GS, C)`, `C = g2^m h2^t`, `t` uniform.

| Hybrid | Change | Justification | Our evidence |
|---|---|---|---|
| H0 | real game, adversary knows sk and the original `(s, r)` | -- | -- |
| H1 | CRS replaced by a hiding CRS (`u2 = t1 u1 - iota(g1)`, same for `v`) | SXDH (computational) | structural test: `test_hiding_crs_trapdoor_identities` |
| H2 | `pi_GS` replaced by the simulated proof, computed from `(X, Y, C, h2)` and the CRS trapdoor only | GS perfect ZK for this statement | `tests/test_gs_simulator.py` |
| H3 | `C` replaced by a uniform G2 element | Pedersen perfect hiding, `t` uniform | `commit_g2` docstring; `test_message_hiding.py` (smoke only) |

In H3 the whole output is independent of `m`, `s`, `r`, `sk`, so even full key
and signature exposure gives advantage 0 beyond the SXDH step.

**Why the simulator exists for our three PPEs.** Commit every variable to the
identity and run the honest prover. E2, E3 have target `1`, so the honest
equation already holds. E1 has target `e(g1, g2)` whose discrete logs are
known (both generators), so `iota_T(e(g1,g2)) = F(iota(g1), iota(g2))` can be
rewritten through the trapdoor `iota(g1) = t1 u1 - u2` and absorbed into
`pi` (`pi_1 -= t1 iota(g2)`, `pi_2 += iota(g2)`). No discrete log of `h2`, `X`,
`Y` or `C` is needed; for E2/E3 the constants only appear in the randomness
terms the prover computes anyway. (A general PPE with a target of unknown
discrete log would not be simulable this way -- this is a property of *our*
statement, not of GS in general.)

Tests establish: simulated proofs verify under the hiding CRS, including for
a **false** toy statement; they fail without the trapdoor correction; they are
rejected under a binding CRS (soundness is not undermined). They do not
establish indistinguishability of the two CRS types (that is SXDH itself) nor
statistical equality of real and simulated transcripts.

## 3. Unforgeability (Thm 5.3) -- full reduction, with its assumption made explicit

**Game.** Challenger: `(X, Y)` BB keys, `h2`, CRS; adversary `F` gets a
signing oracle (it may be given the concealed signature and opening for each
queried `m_i`), and outputs `(sigma_CS*, m*, t*)` with `CVerify = 1`,
`Decom(m*, sigma_CS*, t*) = 1` (so `C = g2^{m*} h2^{t*}`) and `m*` not queried.

**Extraction (binding CRS).** The CRS is generated by the reduction, which
keeps the extraction trapdoor (same distribution as the real CRS). Perfect
soundness of GS gives group elements `(s, w1, w2, xt, xr)` satisfying E1-E3.
By E2/E3 and prime order there are integers `t', r'` with
`w1 = h2^{-t'}, xt = g1^{t'}, w2 = Y^{r'}, xr = g1^{r'}`, and E1 reads

    e(s, X C h2^{-t'} Y^{r'}) = e(g1, g2).                              (*)

**The assumption the paper's proof silently uses (EE).** The extractor yields
`xt = g1^{t'}`, `xr = g1^{r'}` -- *group elements*. The reduction below needs
the *integers* `t', r'`. We therefore state:

> **(EE) Exponent extractability.** There is an efficient extractor that, given
> the CRS trapdoor and an accepting proof produced by an efficient adversary,
> outputs integers `(t', r')` consistent with (*), except with negligible
> probability.

(EE) is not implied by GS perfect soundness (which only extracts group
elements) and is not a standard assumption. It holds, e.g., in the algebraic
group model (AGM), where every group element the adversary outputs comes with
its representation in the elements it received; we do not reproduce an AGM
proof here. Treat Thm 5.3 below as **conditional on EE** (plus q-SDH and DL).

**Theorem 5.3 (conditional).** Under (EE), for every efficient `F`
`Adv_forge(F) <= Adv_BB-EUF-CMA(B) + Adv_DL(D)`, with `B`, `D` below; BB04's
full-CMA scheme `g1^{1/(x+m+yr)}` is existentially unforgeable under q-SDH
(Boneh-Boyen, EUROCRYPT 2004; cite the full-CMA section -- check the
numbering before quoting), hence `Adv <= Adv_q-SDH + Adv_DL`, and DL <= q-SDH.

**Reduction B (to BB unforgeability).** `B` receives `(X, Y)` and a BB signing
oracle. It picks `k <- Zp*`, sets `h2 = g2^k`, generates a binding CRS with
trapdoor, and answers `F`'s signing query `m_i` by asking its oracle for
`(s_i, r_i)`, choosing `t_i`, and returning the concealed signature / opening
(all computable from public data). On `F`'s output it extracts `(s, t', r')`
by (EE) and sets

    m' := m* + k (t* - t')  (mod p).

Since `C = g2^{m*} h2^{t*}`, `X C h2^{-t'} Y^{r'} = X g2^{m'} Y^{r'}`, so (*)
says exactly `e(s, X g2^{m'} Y^{r'}) = e(g1, g2)`: **`(s, r')` is a valid BB
signature on `m'`** (checked on real objects in
`tests/test_reduction_algebra.py`). `B` outputs it. It is a forgery iff
`m' not in {m_i}`.

Case analysis (this is the part the paper leaves out):

1. `t' = t*`: then `m' = m*`, fresh by the game's freshness condition.
2. `t' != t*`, `m'` not queried: `m'` is fresh -> forgery.
3. `t' != t*`, `m' = m_i` for a queried `m_i`: `B` fails; this event is
   bounded by `D`.

**Reduction D (to DL of `h2`).** `D` gets `h2 = g2^k` with `k` unknown. It
generates `(x, y)` itself, so it can answer every signing query, builds the
CRS with trapdoor, runs `F`, extracts `(t', r')` by (EE). In case 3,
`m* + k (t* - t') = m_i` gives `k = (m_i - m*) / (t* - t')` (the denominator is
non-zero). This covers in particular a forger that re-opens the commitment of
a queried signature to a different message: its `C` equals `g2^{m_i} h2^{t_i}`
and also `g2^{m*} h2^{t*}`, the extracted `t'` is `t_i`, and `m' = m_i`
(again verified numerically). The view of `F` in `B` and in `D` is identically
distributed (uniform `h2`, honest CRS, honest signatures), so the same event
has the same probability, and `Pr[forge] <= Pr[case 1 or 2] + Pr[case 3]`.

**Where each ingredient of the paper's three-line proof is used.** q-SDH ->
BB unforgeability (cases 1-2); DL/Pedersen binding -> case 3; GS soundness ->
the extraction step, which however only delivers group elements, hence EE.

**What remains open.** (EE) itself. Options for the report: (a) state the
theorem as above, conditional on EE, and note the AGM justification;
(b) argue in the AGM/generic bilinear group model (a real proof is long --
the representations of `xt, xr` in terms of the oracle responses
`g1^{1/(x+m_i+y r_i)}` must be tracked as rational functions of `x`);
(c) replace GS scalar witnesses by a Fiat-Shamir sigma protocol for
`(t, r)` (changes the construction; the paper does not do this).

## 4. Trusted setup and parameter provenance

* `gs.CRS.generate` samples the extraction trapdoors and drops them. Python
  gives no guarantee of erasure; in a deployment the CRS must come from an
  MPC ceremony or a trusted party. Whoever holds the trapdoors opens every
  commitment -- message hiding is lost (and, with the hiding-mode trapdoor,
  false statements become provable).
* `PublicParameters.is_valid` checks curve/subgroup membership and a few
  structural facts. It **cannot** certify that the CRS is binding-mode or
  honestly generated: a hiding CRS passes every check (see
  `test_simulated_proof_rejected_under_binding_crs` for the contrast).
* `h2` is derived by hash-to-G2 from a public seed so nobody knows
  `log_{g2} h2`; custom-supplied `h2` must be trusted separately.
* Messages are hidden from the *verifier of the proof*, not from anyone who can
  guess `m` and test it against a revealed `t`; `t` must stay secret and fresh
  (reuse leaks `m2 - m1`, tested in `test_edge_cases.py`).
* No range/positivity proof (see `AMBIGUITIES.md`); not constant-time (pure
  Python), so no side-channel claims.

## 5. Review of `gs.py` / `concealed.py` (A's review items)

* `verify_ppes` checks every proof/commitment/CRS point for subgroup
  membership before pairing; `cverify` validates keys, `C`, parameters and
  proof shape and converts malformed inputs to `False`. No defect found.
* `Decom` alone does not authenticate the signature (documented; applications
  must require CVerify AND Decom).
* **Verifier optimisation (done, interface unchanged).** Batching now uses
  rank-one projections `alpha = (a, 1)`, `beta = (b, 1)`: for a non-zero
  2x2 exponent matrix `M`, `alpha^T M beta` is a non-zero polynomial of degree
  <= 1 in each of `a, b`, so Schwartz-Zippel bounds the false-accept
  probability by about `3/p` per batch (2/p projection + 1/p equation weight
  `rho`), the same order as before. Pairing terms sharing a G2 point are merged
  (bilinearity) before the Miller loops, and subgroup checks are memoised on
  affine coordinates (they depend only on the point's value). Single
  `cverify` on the development machine: about 3.8 s -> 2.3 s (single run,
  warm parameters). The benchmark snapshot `bench/results/2026-10-31/` was
  re-run after this change (n=20: CVerify median 2315 ms, 2.22x BB Verify).
* Not done: faster G2 subgroup test (endomorphism-based), fixed-base
  precomputation; they would help further but add risk without a
  reference implementation to cross-check.

## 6. Q&A cheat sheet

* *Why three equations?* GS handles group-element variables; exponents `t, r`
  are encoded as `w1, w2, xt, xr` and tied to fixed bases by E2/E3 (linear).
* *Why is E1's target not a problem for ZK?* known discrete logs of `g1, g2`.
* *Is the proof extractable for `t`?* Only `g1^t`, not `t` -- see §3 gap.
* *What breaks if the CRS trapdoor leaks?* Hiding (openable commitments) and,
  in hiding mode, soundness.
